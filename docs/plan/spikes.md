# Spikes

A spike answers a question whose answer could change the plan. Code and full notes go in `spikes/<name>/`, with a `NOTES.md`.

1. **Extension loading** (`spikes/extension-loading/`): in a compiled `tau` binary, can a user's `.ts` extension import the SDK and get the embedded copy? Can changed extensions be re-imported on `/reload`?
   **Result: yes.** A runtime `Bun.plugin` serves the SDK as a virtual module and wins over an extension's own `node_modules` copy. Reload works by deleting `require.cache` entries under extension dirs (query-string busting misses helper files).
2. **Sandbox** (`spikes/sandbox/`): does QuickJS load from a compiled binary with its WASM embedded? Can scripts await async host functions and be cancelled mid-run?
   **Result: yes.** WASM embeds with `import … with { type: "file" }`. Async host calls run concurrently and abort cleanly. CPU-bound scripts block the main thread, so the real sandbox runs in a `Worker` and is interrupted through a shared flag.
3. **Process sessions** (`spikes/pty/`): from a compiled binary, can `Bun.Terminal` run an interactive program (a shell, `python`), accept input, resize, keep a background server alive across tool calls, and kill the whole process tree with no orphans? A "no" means shipping a PTY helper binary, as OpenCode does.
   **Result: yes on macOS and Linux arm64.** Shell/Python input, resize, server persistence and cleanup pass without a helper. Use `detached: true` to isolate children from Tau's process group. Job-control shells create additional groups, so cleanup must cover owned descendants, not just the root group. Linux passed in an OrbStack Debian 13 container; the tested cleanup covers ordinary shell jobs.
4. **OpenTUI** (`spikes/opentui/`): does an OpenTUI + Solid app with a chat pane and sidebar run from a compiled binary (OpenTUI loads a native Zig library through `bun:ffi`)? Can an extension's `.tsx` file, loaded at runtime, add a sidebar slot? Solid needs a JSX compile step, so the extension loader would run that transform. A "no" on the second question means extension UI uses OpenTUI's plain object API instead of JSX.
   **Result: yes on macOS and Linux arm64.** Streaming markdown, input, sidebar and reactive runtime `.tsx` extension work without `node_modules`, headlessly and in a PTY. OpenTUI's runtime plugin exposes embedded Solid/OpenTUI modules and transforms JSX. Binary size: 82 MiB on macOS, 106 MiB on Linux. Linux passed in an OrbStack Debian 13 container.
5. **Effect** (`spikes/effect/`): should internal layers use Effect 4? A provider stream decoder and a PTY tree kill were each written in plain TypeScript and in Effect, then run in compiled binaries against a fake provider and a job-control shell tree.
   **Result: it works, with negligible cost: +86 KB bundle, same stream speed.** Both versions pass all cancellation and cleanup checks. The difference is how cleanup is reached: plain code needs `reader.cancel()` in `finally`, a signal passed into every wait, and `await using`, and forgetting one leaks silently. Effect cancels at every `yield*` and closes connections and process trees on `take`, timeout or interrupt with no extra code. The SDK can stay promise-based through `Stream.toAsyncIterable` and `runPromise({ signal })`. Effect's HTTP and SSE modules are still marked unstable. Learning cost and debugging were not tested.
6. **Toolchain** (`spikes/toolchain/`): on Bun 1.4.3 and Effect 4.0.3, can `@effect/tsgo` with TypeScript 7 be the only type checker, alongside oxlint type-aware and our own JS plugin? Pass means: one command reports both a type error and an Effect diagnostic and fails on each; a type-aware rule and a custom rule both fire; a rule scoped to one layer fires in `core` and stays silent in `host`; full lint time on a realistic file count is acceptable (type-aware rules and JS plugins run serially; an oxc issue reports about 29 s on about 3,800 files). Dev-tool spike, so the compiled-binary rule does not apply.
   **Result: yes on macOS arm64, with memory and dependency-depth limits.** All 27 behavior checks pass, including both diagnostics in one `tsc` run and layer overrides. On 3,000 generated Effect-heavy files with eight-file dependency chains, types plus Effect take 5.24 s; full lint takes 5.33 s and 4,562 MiB peak RSS. The single-command oxlint `--type-check` variant works but uses 7,248 MiB and remains experimental. Keep separate type and lint tasks with one owner per rule. A 3,000-level schema chain did not complete within the benchmark's 600 s total limit; real-codebase, editor and Linux checks remain untested.
7. **File finder** (`spikes/file-finder/`): does `@ff-labs/fff-bun` work in a compiled binary on macOS and Linux arm64 without copying its native library to `/tmp` on every load (OpenCode issue #54106)? Does it beat fuzzysort and fzf-for-js on a shallow clone of the Linux kernel (gitignored, inside the spike) and a mid-size repo, on time to first result, search speed, memory, and ranking?
   **Result: compiled loading works on macOS and Linux arm64/glibc; a native tie-break fixes the measured ranking omission.** All 11 smoke checks pass on each platform, and native/JavaScript inventories agree at 8,729 and 95,964 files. One cached library keeps the same inode and modification time across six FFF processes per platform; the first load still extracts it. On the kernel tree, stock FFF's median first result is 97 ms on macOS and 159 ms on Linux, versus fuzzysort's 731/1,120 ms. FFF uses less large-tree memory; fuzzysort wins warm-query speed (about 1 ms versus 2–3 ms). FFF finds all four typo targets. The follow-up traces variable ranks to equal-score/equal-time ties in native page selection. A prototype preserves those priorities, then uses path length and lexical order: `schemasession` ranks first in all 270 compiled probes across both platforms, and all 20 targets retain consistent top-ten ranks across five runs per platform. Native regressions and smoke checks pass; matched-build timing shows about 11 ms more OpenCode first-result time on macOS and about 0.4 ms more kernel query p95 on each platform. Use published, unpatched FFF first; reconsider the workaround if a ranking bug is opened. Cold-cache, x64, musl and broader relevance tests remain untested; full measurements and limits are in NOTES.md and RANKING.md.
8. **Effect AI** (`spikes/effect-ai/`): can Effect's AI packages carry every route in [features.md](features.md#models) for chat, structured output and decision models, replay across models, and have their traffic recorded and replayed offline?
   **Result: yes on macOS arm64, with three small Tau adapters.** All 13 cases pass live and offline, under `bun` and from a compiled binary.
   - **Chat:** the Claude and ChatGPT subscriptions, the OpenAI API key and OpenRouter work through `@effect/ai-anthropic`, `@effect/ai-openai`, `@effect/ai-openrouter` and `@effect/ai-openai-compat`. Auth goes through `transformClient`, reading the token on every request.
   - **Replay:** thinking signatures and encrypted reasoning survive `Prompt.fromResponseParts`. Another Claude model accepts Sonnet's signature, and each package ignores other providers' data. Only `@effect/ai-openrouter` keeps OpenRouter's `reasoning_details`.
   - **Structured output:** `generateObject` works on every chat route. Codex needs a `transformClient` shim, because it only streams and adds `phase: "commentary"` messages. OpenRouter needs `strictJsonSchema: true`.
   - **Decision models:** both need Tau's own `DecisionModel.make` adapters. Jev and OpenRouter's Luna use System One (`/api/v1/systemone`), because Effect's OpenRouter decision endpoint returns 404. Luna on OpenAI uses `/v1/decisions`, which refuses subscription tokens.
   - **Caching:** prompt caching works on both subscriptions. Codex needs a `session-id` header.
   - **Untested:** error paths, login flows, Codex WebSockets, OpenCode Go and Linux.
9. **Code mode** (`spikes/codemode/`): can `@opencode/codemode` replace QuickJS as the interpreter behind `run`? Pass means it runs from a compiled binary, Esc stops a busy loop while the event loop keeps ticking, it shares one Effect 4.0.3 copy with Tau, and real model-written scripts run unchanged.
   **Result: yes on macOS arm64; it replaces entry 2's QuickJS plan.** Host calls run concurrently; Esc ends a pending shell call in ~200 ms and kills the child; a busy loop on the main thread stops in ~300 ms while the event loop keeps ticking, so no worker is needed. An `overrides` entry gives one Effect copy, and Tau's Schemas decode inside it. Of 496 distinct `codemode` scripts from Pi sessions, none used unsupported syntax; every failure came from stub tools or invalid JavaScript. Loops run about 50 times slower than QuickJS. Linux is untested.
10. **Live routes** (`spikes/live-routes/`): do Tau's route code, token refresh and decision adapters work against the live services with credentials saved by `tau login`?
    **Result: yes, after two fixes.** Both subscriptions' chat and refresh, and all three decision models, pass (Jev and Luna on OpenRouter's System One; Luna on OpenAI Decisions). Claude subscription requests returned 429 until each carried both the Claude Code identity as the first system block and the headers `user-agent: claude-cli/2.1.280` and `x-app: cli`. Codex non-streaming text came back empty in 2 of 5 calls, because the `response.completed` event sometimes has an empty `output`; the reply is now built from the `response.output_item.done` events. Both fixes pass live. Compiled binary and Linux untested.
11. **Sign in with ChatGPT** (`spikes/sign-in-with-chatgpt/`): can Tau use OpenAI's open-source plan-usage login, with Effect's OpenAI package against the public Responses API?
    **Result: yes, through Tau's existing stream collector.** Registration as "Tau" issued an `oaiapp_…` client ID with the plan scope; the token exchange and a refresh worked, with a one-hour access token and a rotating refresh token. Plain text, a system message, a function tool and structured output all pass. Effect's own non-streaming requests are refused (`Stream must be set to true`), so they go through the collector Tau already uses for Codex. Top-level function tools were accepted, though the docs ask for namespaces. The Decisions API refuses the token (401), so Luna decisions keep the API key. ID-token verification, revocation and the compiled binary are untested.
12. **Package install** (`spikes/package-install/`): planned; the question is in [sdk-packages.md](sdk-packages.md).
13. **OpenAI prompt cache** (`spikes/openai-cache/`): why do the `chatgpt` and `codex` routes read nothing from the prompt cache, and which request change fixes it?
    **Result: the missing `session-id` header.** With only `prompt_cache_key`, 2 of 36 later turns read the cache; with the conversation ID also in a `session-id` header, 28 of 36, on both routes and on Luna and Sol. Tau's requests repeat each other byte for byte, so the prefix was not the cause. Tau now sends the header on the `openai`, `chatgpt` and `codex` routes. These routes always report 0 cache-write tokens. The `openai` API-key route was not tested live.
14. **Live models** (`spikes/live-models/`): do Tau's tools and agent loop work on every model of the [live model matrix](tooling.md#live-model-matrix)? Re-run after a change to the tools, the loop, a protocol or a route.
    **Result: all 12 models pass, after three fixes.** The first run failed three OpenAI runs and Gemini. Effect sent `run` to OpenAI in strict mode, so every optional field became required and nullable: models filled in `scriptId` on new programs, and a call that failed the schema ended the whole run with `Invalid output`. Gemini on OpenRouter sent an empty reply, which Tau took as the answer. Fixes: `run` gives Effect only a JSON schema and Tau checks the parameters, so a wrong call is a failed result the model sees; strict mode is off for `run`, as in OpenCode; an empty reply is retried. In the second run every model passed, and 7 of 12 fixed a failed script with `scriptId` and edits. One OpenCode Go backend (`chatcmpl-tool-` call IDs) dropped every DeepSeek tool parameter, and the model looped on empty calls until stopped; a rerun on DeepSeek's own backend passed. Details in the spike's `NOTES.md`.
15. **Reload** (`spikes/reload/`): can a supervisor restart Tau into new code when Tau is idle, hand the terminal to the next child cleanly, refuse broken code, and fall back to the last good build after a crash? The design is in [reload.md](reload.md).
    **Result: yes,** under `bun` and as a compiled binary on macOS arm64. An idle restart takes 0.55 s from save to new frame, with about 100 ms of empty screen, and keeps the unsent draft. An edit during a run waits for the run to end. A syntax error or a start failure keeps the old build. A crashing build is restarted once, then replaced by the last good build. The terminal is restored after quit and after the supervisor gives up; a crashed child run alone leaves it broken. Bundles need `external` for other platforms' OpenTUI packages and `publicPath` set to the build folder. A compiled binary must set `autoloadBunfig: false`, or a project's `bunfig.toml` breaks it. OpenTUI catches uncaught errors in its console overlay, so only hard exits crash the child. Added for the build: a compiled binary can start itself with IPC, and `bun --config=<empty bunfig.toml> <bundle>` ignores the project's `bunfig.toml`.
16. **Web search** (`spikes/web-search/`): do the provider-side web search tools work through Tau's routes on each provider's small model, and does Exa's hosted MCP endpoint answer without a key?
    **Result: hosted search works on the Claude subscription, Codex, ChatGPT app and OpenAI key routes; Exa without a key is rate limited.** Each route answered in 4–9 s with inline Markdown links. Claude returns titled `source` parts; the OpenAI routes put URLs in the tool result's `action.sources` and rarely return `source` parts, so sources come from both. Exa answered HTTP 200 with `_meta["ai.exa/rateLimited"]: true` and a request for a key, so that reply must count as a failure. Exa with a key and the compiled binary are untested.
