# Deferred

Decisions to make later. Each line is the question and what brings it up. When that happens, move the item to [questions.md](questions.md).

- Whether the reload supervisor owns process sessions, so dev servers and watchers survive a restart of Tau. This moves the process registry and its output buffers across a process boundary. Comes up when restarts that end long-running processes get in the way ([reload.md](reload.md)).
- OpenTelemetry tracing for enterprises. Comes up when enterprise tracing is requested, or with the live inspector ([features.md](features.md#interface)).
- The live inspector's design: how processes find the server, what is kept, how bodies are captured. Comes up after the TUI (step 6), or sooner if debugging a provider needs it.
- How npm delivers the binary: a launcher plus one package per platform, or the npm package holds only SDK types and the binary installs separately. Comes up at build step 8.
- Whether a separate raw shell tool beats a shell function inside the sandbox. Comes up once the agent loop runs.
- OS-level confinement for commands that `run` starts: Seatbelt (`sandbox-exec`) on macOS, Landlock or bubblewrap on Linux, as Codex CLI and Claude Code do, limiting writes to the workspace and network to an allowlist. Could be a replaceable SDK part with the OS sandbox as Tau's default. Comes up at build step 4.
- Whether Tau runs well inside NVIDIA OpenShell (a container sandbox with a gateway and credential injection) for users who want that containment. OpenShell is not Tau's runtime: it wraps the whole agent, needs a container runtime and a gateway service, and keeps credentials outside the agent. Comes up when a user runs Tau inside it, or at build step 8.
- Prompt cache mechanics: Claude's third and fourth cache marks and its 1-hour lifetime; OpenAI's explicit cache mode (`prompt_cache_options`, `prompt_cache_breakpoint`, 30 minutes), which Effect's OpenAI provider exposes; where each provider takes cache markers; building the compaction request from the same system prompt, functions and history with only the summary instruction appended (OpenCode PRs #25100 and #42506 estimate about 90% savings), and showing the cache hit rate in the sidebar. Comes up at build step 5.
- Replay: comparing context methods (whole history, notes, notes with memory) on recorded sessions. Offline replay only measures context size and prefix reuse; judging whether a method keeps the agent on track needs live reruns with workspace snapshots, safe tool execution and paid calls. Comes up when real long sessions exist after the TUI (step 6), or when tuning the note and dream thresholds needs evidence.
- Custom type-aware lint rules. Comes up when TypeScript 7.1 ships its JS API.
- A versioned source for TypeScript 7 compiler-option docs. Comes up when an agent misconfigures `tsconfig.json` from the README alone, or when the TypeScript website documents 7.x.
- Whether a generated module map would improve helper discovery. Comes up when reuse-first planning misses an existing helper.
- Whether to carry FFF's native tie-break patch. Comes up if a ranking bug is opened after trying unpatched FFF; prefer an upstream fix over maintaining native binaries.
- web-tree-sitter or `@ast-grep` for code-structure tools. Comes up when those tools are rebuilt.
- OS keychain storage, encryption at rest, several accounts per provider, or per-project credentials. Comes up when a user or enterprise asks for one.
- Whether Fallow follows dynamically loaded default exports. Comes up when the extension host loads modules by path.
- The exact 49/50-token duplicate thresholds. Comes up when a duplicate report looks wrong near the threshold.
- Whether development hooks rerun checks after a live session's files change. Comes up when a hook misses a change in a live session.
- The Codex `session_id` header and priority tier. Comes up at build step 4, when the agent loop calls models with the session ID.
- Refreshing OAuth tokens in the background before a request needs them. Comes up if a refresh noticeably delays a request.
- A live token refresh on the `chatgpt` route through Tau's code (offline tests cover it). Comes up at the next live check.
- Whether Tau reloads `~/.tau/settings.json` when it changes, or only on start. Comes up at build step 7, with extension hot reload.
- The finish reason on assistant entries (usage is already saved). Comes up at build step 5, when compaction needs the context size.
- Reading only new entries each step instead of rereading the whole session, so a long session does not slow every step. Comes up at build step 5.
- A `child` session origin for subagents. Comes up at build step 7; the origin is JSON, so it needs no migration.
- Images and files in user entries, session titles, and deleting or exporting sessions. Comes up with the TUI (step 6), the auto-name extension and manage-sessions.
- The HTTP fake provider that speaks all three protocols ([architecture.md](architecture.md#testing)). Comes up with the first flow that depends on protocol behavior, such as prompt caching or tool-history repair. When it is built, move the agent-loop tests from the scripted in-process model to it and delete the scripted model. Also move the login tests' signed-header checks to it and remove the `tests` → `ai-internal` allowance in `.fallowrc.jsonc`.
- Multi-repository sessions and projects ([features.md](features.md#context)). Comes up before build step 6, because the session list depends on it.
- Cache warnings, the long-lived cache setting, `/settings`, and asking to compact when the cache is cold and the context is large ([features.md](features.md#interface)). The TUI parts come up at build step 6; asking to compact comes up at build step 5.
- A loop guard, on by default: the same script with the same result several times in a row gets a nudge, then ends the run; identical replies end the run; a reply that repeats itself while streaming is stopped and retried once. Goose's `RepetitionInspector` and OpenCode's `doom_loop` permission are the nearest designs. Comes up when a run is seen looping. Slice 4d's repeat limit ends the run with no nudge first; revisit it when nudges exist.
- Claiming a session so two Tau processes cannot run it at once. Two TUI tabs on one session can mix their histories and run one tool call twice. Comes up with the TUI's session picker at build step 6.
- Rereading `user_version` inside the migration's write lock. Two Tau processes started together right after an upgrade can both apply a new migration; the second fails to start and a restart works. Comes up if a user reports that startup error.
- Print mode writes a failed attempt's streamed text to stdout before the retry, so `tau -p "..." > out.txt` can hold half a reply after a mid-reply rate limit. Buffer each attempt, or emit an attempt-failed event. Comes up if someone scripts print mode.
- Not counting interrupted replies against `maxTurns`. Comes up if a user reports a run stopping a turn early.
- More uses of nudges (hidden model notes, first built for context stages in slice 5a): user skill invocation at step 6, loop warnings, cut-output guidance and fallback-check reminders. Comes up when those flows use the shared nudge entry.
- Recovering from a "context too long" error (an automatic checkpoint without a handoff, then one retry). The budget keeps the context at least 16k below the window and tool output is capped. Comes up if a session overflows anyway.
- PTY process kill misses a child spawned during the kill, and signals descendants by pid, so a reused pid could be hit. Pipe sessions kill by process group and are not affected. Comes up if a leaked child is reported, or when a supervisor for surviving Tau's exit is built.
